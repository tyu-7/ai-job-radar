# AI Job Radar

一个面向校招与职场早期候选人的 AI 岗位雷达 Skill：依据可配置的候选人画像，持续完成岗位检索、资格核验、匹配评分、去重、风险提示和投递追踪。

> 仓库中的候选人、公司、岗位、链接和数据均为虚构示例，不包含真实简历、投递记录或本地配置。

## 为什么做这个项目

校招岗位分散在公司官网、公众号和招聘平台，人工重复搜索的成本高，还容易遗漏截止时间或重复投递。AI Job Radar 将“发现岗位”与“是否值得投”拆开：先核验事实，再按个人偏好评分，最后生成当日行动清单。

## 人与 AI 的分工

| 人负责 | AI 负责 |
| --- | --- |
| 定义目标岗位、城市、风险边界和硬性约束 | 检索公开岗位并抽取结构化 JD 信息 |
| 提供真实且可证明的经历与能力 | 校招资格核验、匹配评分、关键词统计和去重 |
| 判断是否投递并维护申请状态 | 生成推荐理由、风险提示和面试追问 |
| 最终核验关键事实与做出决策 | 增量更新追踪表；失败时降级为只生成简报 |

项目适合使用具备联网检索、工具调用和结构化文件处理能力的模型（例如 Codex 中的工具型 GPT 模型）。选择重点不是单轮文案能力，而是能否跨网页、规则和追踪文件完成可审计的任务链。

## 核心设计

- **先资格、后评分**：毕业年份、岗位性质和截止状态不符合时直接排除。
- **100 分匹配模型**：综合岗位方向、个人证据、平台成长、城市、时效和风险。
- **双重去重**：规范化直达链接 + `公司｜岗位｜城市` 指纹。
- **人类字段保护**：AI 不覆盖投递状态、投递日期、简历版本和个人备注。
- **失败降级**：网页或表格环节失败时仍按时输出简报，并明确未保存部分。

## 快速使用

1. 复制 `assets/candidate-profile.example.yaml`，填写自己的目标与约束。
2. 将本目录作为 Codex Skill 使用，并通过 `$ai-job-radar` 发起岗位检索。
3. 首次运行可使用 `assets/job-tracker-template.xlsx`；后续运行在同一文件中增量更新。
4. 人工核验后再投递。本项目不会自动提交申请或联系招聘方。

示例请求：

```text
使用 $ai-job-radar，根据 candidate-profile.yaml 检索最近 72 小时更新的校招岗位，
去重后给出前 10 个岗位，并更新岗位追踪表。无法核验的信息请明确标记。
```

## 隐私与公开边界

公开仓库只应保留通用画像字段、评分规则、空白模板和虚构示例。不要提交以下内容：真实姓名和联系方式、教育或工作经历原文、真实投递状态、私有仓库地址、登录态数据、API 密钥、本机绝对路径，以及招聘网站的非公开页面内容。

## 局限

- 岗位页面可能动态加载、下线或限制访问，最终信息以公司官方招聘页面为准。
- 匹配分用于排序而非替代职业判断，不代表录用概率。
- 定时运行由宿主平台负责，本仓库不包含个人时区、任务 ID 或本机调度配置。
